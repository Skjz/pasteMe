# 0010 自动更新自己写，用编进应用的 Ed25519 公钥验证 DMG

日期：2026-10-25

用户希望 PasteMe 自己发现新版本、装好并重新打开，不用再去 GitHub 看。发布版用的是临时签名（`scripts/make-dmg.sh` 开头写了原因），系统认不出发布者：换一个内容的 DMG，`codesign --verify` 照样通过。自动安装又不经过用户的眼睛，谁能往 GitHub 的发布里传文件，谁就能把任意程序装到每个用户的 Mac 上，还带着辅助功能权限的提示。

现在的做法（`Updates.swift`、`Updater.swift`）：

- 发布者用 `swift scripts/update-signing.swift generate` 生成一对 Ed25519 钥匙，私钥只存在自己的登录钥匙串里，公钥写在 `UpdateSignature.publicKey`。`make-dmg.sh` 打完 DMG 用私钥签名，生成 `PasteMe-x.y.z.dmg.sig`，和 DMG 一起传到发布里；钥匙串里的私钥和 `Updates.swift` 里的公钥对不上就停下。钥匙串里这一项不信任任何应用，每次读取都要输入登录钥匙串的密码；只信任创建它的 swift 解释器的话，本机任何 Swift 脚本都能不声不响地读走它（2026-10-25 审查 #55 时指出，用 `SecKeychainSetUserInteractionAllowed(false)` 确认过）。恢复用 `restore`，私钥不进命令参数和 shell 历史。
- 应用每天向 `api.github.com` 查一次最新的发布（设置的「关于」页可以关掉，默认打开），请求不带 Cookie、不带任何内容。有新版本时只在菜单栏菜单里放「更新到…」并显示一次 Toast，不弹窗；手动检查才弹窗。
- 用户点了安装才下载。签名验证不过不装；挂载 DMG 后检查 bundle id 是发布版、版本和 tag 一样（不能拿旧版本的签名包冒充新版本）、`codesign --verify` 通过，然后 `replaceItemAt` 换掉正在运行的应用，退出，由一个等进程结束的 shell 重新打开。
- 开发版不自动检查，手动检查只给下载页面。

## Considered Options

- Sparkle：成熟，也用 Ed25519 签名，但它是第三方框架，违反 ADR 0001；SwiftPM 的二进制依赖还要在 `bundle.sh` 里手动嵌进应用、重新签名。PasteMe 只需要「查一个 JSON、下一个 DMG、换一个应用」，自己写不到 300 行。
- 只核对 GitHub 给的 SHA-256：能挡住下载出错，挡不住 GitHub 账号或发布流程被人拿到。
- 只提示、让用户自己去发布页下载：最简单，用户选了自动替换。
- Developer ID 签名加公证：需要付费的开发者账号，现在没有。有了以后系统就能认出发布者，签名这一道仍然可以留着。

## Consequences

- 私钥丢了，已经装好的版本就再也自动更新不了，只能让用户手动下载一次带新公钥的版本。备份方法写在 `scripts/update-signing.swift` 开头。私钥泄露时同样要换钥匙、让用户手动更新。
- 发布时 DMG 和 `.sig` 都要传。缺了 `.sig` 或签名对不上的发布当作不是发布者传的：自动检查不提示，手动检查只警告、不给下载页面，免得用户手动安装、点「仍要打开」绕过校验。0.1.0 没有这个功能，从 0.1.0 升上来的用户要手动下载一次。
- 签名只证明「这个 DMG 是发布者签过的某一版」，不证明「这是最新的一版」。拿到 GitHub 发布权限的人可以把 latest 换成一个以前签过的、比用户手上新的旧版本（用户在 0.2.0，真正最新的是 0.4.0，却装上 0.3.0），校验照样通过；也可以一直不更新 latest，让用户停在旧版本。不能降级：比用户手上旧或一样的版本不会提示，DMG 里的版本必须和 tag 一样。要挡住这一种，得把「这是最新版」也签进去（比如签一份带版本号和时间的清单，客户端记住见过的最高版本），现在没有做。
- 临时签名每次构建都不一样，更新后辅助功能里的旧条目失效。更新的弹窗里写明了要删掉旧的、重新允许。
- 应用要能写自己所在的文件夹。从 DMG 里直接打开、被系统挪到 App Translocation 里运行、或者用户没有写「应用程序」的权限时，改为打开下载页面（只认这个项目在 GitHub 上的页面）。
- 这是 PasteMe 在后台联网的第二个地方（另一个是默认关闭的链接预览）。
