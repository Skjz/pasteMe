# 0003 ClipStore 保持单线程使用，不改成 actor，也不加锁

日期：2026-10-16

`ClipStore` 是非 `Sendable` 的类，应用里只在主线程使用。OCR、链接预览等后台任务只在后台线程计算，返回 `Sendable` 的结果，再回到主线程写库。之所以不改成 actor 或加锁的线程安全类型，是因为工单 #1–#13 里没有任何场景需要多个线程同时访问数据库，而 actor 会让面板的每次查询都变成异步调用，徒增界面代码的复杂度。Swift 6 的并发检查会在编译期阻止把 `ClipStore` 带到其他线程。

MCP 服务（ADR 0005）运行在另一个进程，持有自己的只读 `ClipStore` 实例，靠 SQLite 的 WAL 模式和 `busy_timeout` 与应用并存，不受本决定影响。

## Consequences

- 若将来出现需要在后台线程直接读写数据库的需求（例如大批量导入），再重新评估；届时可以给 `ClipStore` 加一个串行队列，接口仍保持同步。
- 主线程上的查询必须保持很快。`ClipQuery` 的验收标准是 10,000 条条目时查询 < 50ms（见 #4）。
